## Loading, linking, initialising {#ch02-phases .th}

Each class goes through three phases:

1. **Loading**: a class loader finds the bytes (a `.class` file, a JAR entry, a module image, generated bytes) and the JVM parses them into an internal class structure in **metaspace**.
2. **Linking**:
   - **verification** checks the bytecode (Chapter 1);
   - **preparation** allocates static fields and sets them to default values (`0`, `false`, `null`);
   - **resolution** turns symbolic references in the constant pool into direct ones. HotSpot does this lazily, the first time each instruction runs.
3. **Initialisation**: runs the class's static initialiser, a method the compiler names `<clinit>` that contains every static field initialiser and `static {}` block in source order.

```java run=c02-lazy
public class Lazy {
    static class Heavy {
        static { System.out.println("Heavy initialised"); }
        static void use() { System.out.println("Heavy.use()"); }
    }

    public static void main(String[] args) {
        System.out.println("main starts");
        Class<?> k = Heavy.class;            // loading, but no initialisation
        System.out.println("got " + k.getSimpleName());
        Heavy[] array = new Heavy[3];        // array of Heavy: still no initialisation
        System.out.println("array of " + array.length);
        Heavy.use();                         // first active use
        Heavy.use();
    }
}
```

`Heavy.class` and `new Heavy[3]` need the class to be loaded but do not initialise it. The static block runs exactly once, just before the first call to a static method.

### What triggers initialisation

A class is initialised immediately before the first of:

- `new` of the class;
- a call to one of its static methods;
- a read or write of one of its static fields, **unless** the field is a compile-time constant;
- reflection such as `Class.forName("Name")` (with the default `initialize = true`);
- initialisation of a subclass (superclasses are initialised first; interfaces are not, unless they have default methods);
- being the class whose `main` method is launched.

```java run=c02-triggers
public class Triggers {
    static class Parent {
        static { System.out.println("Parent init"); }
        static int counter = 10;
    }
    static class Child extends Parent {
        static { System.out.println("Child init"); }
        static final int CONSTANT = 42;              // compile-time constant
        static final Integer BOXED = 7;              // not a constant expression
    }

    public static void main(String[] args) throws Exception {
        System.out.println(Child.CONSTANT);           // inlined: nothing initialised
        System.out.println(Child.counter);            // field of Parent: only Parent initialised
        System.out.println("--");
        System.out.println(Child.BOXED);              // Child initialised now
        Class.forName("Triggers$Child");              // already done: no output
    }
}
```

`Child.CONSTANT` is a `static final` primitive initialised with a constant expression, so `javac` copies the value `42` into the caller's bytecode and the class is never touched. `Child.counter` is declared in `Parent`, and the JVM initialises only the class that declares the field.

:::trap
Because constants are copied into the code that uses them, changing `static final int TIMEOUT = 30` to `60` in a library has no effect on already-compiled callers until they are recompiled. Use a non-constant initialiser (or a static method) for values that may change between releases.
:::

## Initialisation order {#ch02-order .th}

### Static order

Inside `<clinit>`, static field initialisers and static blocks run in the order they appear in the source. A static method called during initialisation can therefore see a field that has not been assigned yet:

```java run=c02-static-order
public class StaticOrder {
    static int a = initA();
    static int b = 5;
    static int c;
    static {
        c = a + b;
        System.out.println("static block: a=" + a + " b=" + b + " c=" + c);
    }

    static int initA() {
        System.out.println("initA sees b=" + b);
        return b * 2;
    }

    public static void main(String[] args) {
        System.out.println(a + " " + b + " " + c);
    }
}
```

`initA` runs before `b = 5`, so it reads the default `0` and `a` ends up `0`.

### Instance order

`new C(args)` does:

1. allocate the object with every field at its default value;
2. call the constructor, whose first action is `super(…)` (explicit or implicit), recursively up to `Object`;
3. after `super(…)` returns, run **instance field initialisers and instance `{}` blocks** in source order;
4. run the rest of the constructor body.

If a superclass constructor calls an overridable method, the subclass's override runs **before** the subclass's fields are initialised:

```java run=c02-ctor-virtual
public class CtorVirtual {
    static class Base {
        Base() {
            System.out.println("Base ctor calls describe(): " + describe());
        }
        String describe() { return "base"; }
    }

    static class Derived extends Base {
        private final String name = "derived".toUpperCase();
        private final int size;
        Derived() {
            super();
            size = 3;
            System.out.println("Derived ctor: " + describe());
        }
        @Override String describe() { return name + "/" + size; }
    }

    public static void main(String[] args) {
        new Derived();
    }
}
```

When `Base()` runs, `name` is still `null` and `size` is still `0`, even though `name` is `final`. This is why constructors should never call methods that subclasses can override.

There is a twist: had the field been `private final String name = "derived";`, the override would print `derived/0`. A `final` field of type `String` or a primitive, initialised with a constant expression, is a **constant variable**, and `javac` replaces every read of it with the literal, so it never looks uninitialised. The `toUpperCase()` call makes the initialiser non-constant, which is the usual case for real fields.

## Class loaders {#ch02-loaders .th}

A **class loader** turns a binary name into a `Class` object. Since Java 9 the built-in hierarchy is:

- the **bootstrap** loader (native code, shown as `null`): `java.base` and other core modules;
- the **platform** loader: the remaining Java SE and JDK modules, such as `java.sql`;
- the **application** (system) loader: your class path and module path.

Loaders use **parent delegation**: `loadClass(name)` first asks its parent, and only if the parent cannot find the class does it look itself. That guarantees `java.lang.String` always comes from the bootstrap loader, so no application can substitute its own.

```java run=c02-hierarchy
public class Hierarchy {
    public static void main(String[] args) {
        ClassLoader app = Hierarchy.class.getClassLoader();
        System.out.println(app.getName() + " -> " + app.getParent().getName() + " -> " + app.getParent().getParent());
        System.out.println(String.class.getClassLoader());
        System.out.println(java.sql.Connection.class.getClassLoader().getName());
        System.out.println(ClassLoader.getSystemClassLoader() == app);
    }
}
```

### A class is name plus loader

At run time a class is identified by its **fully qualified name and its defining loader**. The same bytes loaded by two different loaders give two distinct, incompatible classes. That is how application servers isolate deployments and how plugins can carry different versions of the same library, and it is also the source of baffling errors such as "`ClassCastException`: class Foo cannot be cast to class Foo":

```java run=c02-two-loaders
import java.nio.file.*;

public class TwoLoaders {
    public static class Plugin {
        public String hello() { return "hi from " + getClass().getClassLoader().getName(); }
    }

    static class BytesLoader extends ClassLoader {
        BytesLoader(String name) { super(name, TwoLoaders.class.getClassLoader()); }
        @Override
        protected Class<?> loadClass(String name, boolean resolve) throws ClassNotFoundException {
            if (!name.equals("TwoLoaders$Plugin")) return super.loadClass(name, resolve);   // delegate everything else
            synchronized (getClassLoadingLock(name)) {
                Class<?> c = findLoadedClass(name);
                if (c == null) {
                    try {
                        byte[] b = Files.readAllBytes(Path.of("TwoLoaders$Plugin.class"));
                        c = defineClass(name, b, 0, b.length);
                    } catch (java.io.IOException e) {
                        throw new ClassNotFoundException(name, e);
                    }
                }
                return c;
            }
        }
    }

    public static void main(String[] args) throws Exception {
        Class<?> a = new BytesLoader("loaderA").loadClass("TwoLoaders$Plugin");
        Class<?> b = new BytesLoader("loaderB").loadClass("TwoLoaders$Plugin");
        Object instance = a.getConstructor().newInstance();
        System.out.println(a.getName().equals(b.getName()) + " " + (a == b) + " " + (a == Plugin.class));
        System.out.println(a.getMethod("hello").invoke(instance));
        try {
            Plugin p = (Plugin) instance;
        } catch (ClassCastException e) {
            System.out.println("ClassCastException: " + e.getMessage().replaceAll(" @[0-9a-f]+", ""));
        }
    }
}
```

This loader breaks delegation for one class on purpose (child-first), like a servlet container loading a web application's own copy of a library.

## Initialisation is thread-safe {#ch02-threads .th}

The JVM guarantees that a class is initialised **once**, even when many threads trigger it at the same time: each class has an initialisation lock, one thread runs `<clinit>`, and the others wait until it finishes and then see all its writes. That guarantee gives the cleanest lazy singleton in Java, the **initialisation-on-demand holder**:

```java run=c02-holder
public class Holder {
    static class Config {
        private Config() { System.out.println("Config created"); }
        private static class Instance {
            static final Config VALUE = new Config();
        }
        static Config get() { return Instance.VALUE; }
    }

    public static void main(String[] args) throws Exception {
        System.out.println("start");
        Thread[] ts = new Thread[8];
        Config[] seen = new Config[8];
        for (int i = 0; i < 8; i++) {
            int n = i;
            ts[i] = new Thread(() -> seen[n] = Config.get(), "worker-" + i);
            ts[i].start();
        }
        for (Thread t : ts) t.join();
        boolean same = true;
        for (Config c : seen) same &= c == seen[0];
        System.out.println("one instance: " + same);
    }
}
```

`Config` is created only when `get()` first touches `Instance`, exactly once, with no `synchronized` or `volatile` in sight. Which worker thread happens to create it varies between runs; the others block on the class's initialisation lock until it is done.

### When initialisation fails

If `<clinit>` throws, the first user sees `ExceptionInInitializerError`, and the class is marked as erroneous. **Every later** attempt to use it throws `NoClassDefFoundError: Could not initialize class …`, which is confusing because the class file clearly exists:

```java run=c02-init-failure
public class InitFailure {
    static class Broken {
        static final int VALUE = Integer.parseInt(System.getProperty("broken.value", "not a number"));
    }

    public static void main(String[] args) {
        for (int i = 0; i < 2; i++) {
            try {
                System.out.println(Broken.VALUE);
            } catch (Throwable t) {
                System.out.println(t.getClass().getSimpleName() + ": " + (t instanceof ExceptionInInitializerError ? t.getCause() : t.getMessage()));
            }
        }
    }
}
```

When you see `NoClassDefFoundError: Could not initialize class`, look further back in the logs for the original `ExceptionInInitializerError`.

## Concept and tricky questions {#ch02-concept .dr}

:::drill concept
Name the three phases a class goes through and what happens in linking.
---
**Answer.** Loading (find bytes and create the class structure), linking (verification of bytecode, preparation of static fields with default values, and resolution of symbolic references, usually lazily), and initialisation (running `<clinit>`: static initialisers in source order).

**Why.** Static fields exist with default values after preparation, which is why code running during initialisation can observe `0` or `null`.
:::

:::drill tricky
Does `Foo.class` or `new Foo[10]` run `Foo`'s static initialiser?
---
**Answer.** No. Both need `Foo` to be loaded, but neither is an "active use". Initialisation happens on `new Foo()`, a static method call, a non-constant static field access, `Class.forName("Foo")` or initialisation of a subclass.

**Why.** Lazy initialisation keeps start-up fast and is what makes the holder idiom work.
:::

:::drill tricky
`Lib.TIMEOUT` is `public static final int TIMEOUT = 30;`. The library is upgraded with `TIMEOUT = 60`, but your application still uses 30. Why?
---
**Answer.** `TIMEOUT` is a compile-time constant, so `javac` copied the literal 30 into your application's bytecode. The new library is never consulted for that value until you recompile.

**Why.** Constants of primitive or `String` type initialised with constant expressions are inlined (JLS §13.1). Expose such values through a method or a non-constant field if they may change.
:::

:::drill concept
What is the order of execution when `new Child()` runs, with fields, instance blocks and constructors in both `Parent` and `Child`?
---
**Answer.** Allocation with defaults; `Child()` calls `super()`; `Parent`'s field initialisers and instance blocks in source order; the rest of `Parent()`; then `Child`'s field initialisers and instance blocks; then the rest of `Child()`. Static initialisers of both classes ran earlier, `Parent` first, when the classes were first initialised.

**Why.** Instance initialisers are compiled into each constructor right after the `super(…)` call.
:::

:::drill concept
What is parent delegation and why does the JVM use it?
---
**Answer.** A class loader asks its parent to load a class before trying itself. It ensures core classes always come from the bootstrap loader (so no one can replace `java.lang.String`) and that each class is loaded once by the highest loader that can see it.

**Why.** Containers sometimes invert it (child-first) for application libraries, which is powerful but causes duplicate-class problems.
:::

:::drill tricky
How can `ClassCastException: class com.x.Foo cannot be cast to class com.x.Foo` happen?
---
**Answer.** The object's class and the target class have the same name but were defined by different class loaders, so they are different classes. Typical causes: a plugin or web application bundling its own copy of a library, or hot-reload tools.

**Why.** At run time a class's identity is (binary name, defining loader). Modern JVMs include the loader names in the message to make this visible.
:::

:::drill concept
Why is the initialisation-on-demand holder idiom thread-safe without locks in your code?
---
**Answer.** The JVM itself guarantees that a class's static initialiser runs exactly once and that all threads see its effects after it finishes (each class has an initialisation lock). The holder class is initialised only when `get()` first references it.

**Why.** It gives lazy, thread-safe singletons with no `volatile` reads on the fast path. An `enum` with one constant is the other standard choice.
:::

:::drill output
What does this print?

```java run=c02-d-order
public class Order {
```

**Answer.** `As Bs Ai Ac Bi Bc`, then `Ai Ac Bi Bc`. Static blocks run once, superclass first; instance blocks run before each constructor body, superclass part first.

**Why.** This is the most common class-initialisation question in interviews.

:::drill output
What does this print?

```java run=c02-d-static-ref
public class StaticRef {
    static class Base {
```

**Answer.** `Base init`, then `base`. `Sub.name` is really `Base.name`, so only `Base` (the declaring class) is initialised; `Sub`'s static block never runs.

:::drill output
What does this print?


:::drill bug
A `User` subclass crashes with `NullPointerException` in the base constructor. Find the bug and fix it.

```java run=c02-d-bug-template
import java.util.*;

public class Template {
    static abstract class Entity {
        private final String label;
        Entity(String label) { this.label = label; }
        final String describe() { return label + " " + fields(); }
        abstract List<String> fields();
    }

    static class User extends Entity {
        private final List<String> names = List.of("id", "email");
        User() { super("User"); }
        @Override List<String> fields() { return names; }
    }

    public static void main(String[] args) {
        System.out.println(new User().describe());
    }
}
```
---
**Answer.** The original `Entity` constructor called `fields()` to build its description eagerly. That ran `User.fields()` before `User`'s field initialiser had set `names`, so it returned `null`. The fix computes the description lazily in `describe()`, after construction has finished.

**Why.** Never call overridable methods from a constructor. If a value must be computed at construction, pass it to the superclass constructor as an argument.
:::

:::drill bug
After the first request fails, every later request fails with `NoClassDefFoundError: Could not initialize class Settings`, although `Settings.class` is in the JAR. Explain, and change the class so that a bad property gives a clear error each time.

```java run=c02-d-bug-ncdfe
public class Startup {
    static class Settings {
        private static Integer port;
        static int port() {
            if (port == null) {
                String raw = System.getProperty("app.port", "8080x");
                try {
                    port = Integer.parseInt(raw);
                } catch (NumberFormatException e) {
                    throw new IllegalStateException("app.port must be a number, got '" + raw + "'", e);
                }
            }
            return port;
        }
    }

    public static void main(String[] args) {
        for (int i = 0; i < 2; i++) {
            try {
                System.out.println(Settings.port());
            } catch (IllegalStateException e) {
                System.out.println(e.getMessage());
            }
        }
    }
}
```
---
**Answer.** The original parsed the property in a static initialiser. Its `NumberFormatException` became `ExceptionInInitializerError` once, and the class was then permanently marked as failed, so every later use threw `NoClassDefFoundError`. The fix moves the parsing into a method that throws a descriptive exception on every call and leaves the class usable.

**Why.** Avoid static initialisers that can fail; their failure is sticky for the life of the class loader.

## Write the code {#ch02-coding .cd}

:::drill code rating=1400
Write a class loader that loads classes from a `Map<String, byte[]>` (for example classes compiled at run time), delegating everything else to its parent. Compile a small class with `javax.tools.ToolProvider` in memory and load it.
---
```java run=c02-c-memloader
import javax.tools.*;
import java.io.*;
import java.net.URI;
import java.util.*;

public class MemLoader {
    static class MapClassLoader extends ClassLoader {
        private final Map<String, byte[]> classes;
        MapClassLoader(Map<String, byte[]> classes, ClassLoader parent) { super("memory", parent); this.classes = classes; }
        @Override protected Class<?> findClass(String name) throws ClassNotFoundException {
            byte[] b = classes.get(name);
            if (b == null) throw new ClassNotFoundException(name);
            return defineClass(name, b, 0, b.length);
        }
    }

    public static void main(String[] args) throws Exception {
        String src = "public class Greeter implements java.util.function.Supplier<String> { public String get() { return \"compiled at run time\"; } }";
        JavaCompiler compiler = ToolProvider.getSystemJavaCompiler();
        Map<String, ByteArrayOutputStream> out = new HashMap<>();
        JavaFileObject source = new SimpleJavaFileObject(URI.create("string:///Greeter.java"), JavaFileObject.Kind.SOURCE) {
            @Override public CharSequence getCharContent(boolean ignore) { return src; }
        };
        JavaFileManager fm = new ForwardingJavaFileManager<>(compiler.getStandardFileManager(null, null, null)) {
            @Override public JavaFileObject getJavaFileForOutput(Location loc, String name, JavaFileObject.Kind kind, FileObject sibling) {
                return new SimpleJavaFileObject(URI.create("mem:///" + name + ".class"), kind) {
                    @Override public OutputStream openOutputStream() { return out.computeIfAbsent(name, k -> new ByteArrayOutputStream()); }
                };
            }
        };
        boolean ok = compiler.getTask(null, fm, null, null, null, List.of(source)).call();
        Map<String, byte[]> bytes = new HashMap<>();
        out.forEach((k, v) -> bytes.put(k, v.toByteArray()));
        Class<?> c = new MapClassLoader(bytes, MemLoader.class.getClassLoader()).loadClass("Greeter");
        @SuppressWarnings("unchecked")
        java.util.function.Supplier<String> g = (java.util.function.Supplier<String>) c.getConstructor().newInstance();
        System.out.println(ok + " " + g.get() + " via " + c.getClassLoader().getName());
    }
}
```

Overriding `findClass` (not `loadClass`) keeps parent delegation intact: `Supplier` and `String` come from the bootstrap loader, so the cast to `Supplier` works because both sides agree on that interface.
:::

:::drill code rating=1300
Write a thread-safe lazy cache of expensive per-type objects keyed by `Class<?>`, where each value is created at most once, using `ClassValue`, and show that it computes once per class even across threads.
---
```java run=c02-c-classvalue
import java.util.concurrent.atomic.AtomicInteger;

public class PerClass {
    static final AtomicInteger computed = new AtomicInteger();

    static final ClassValue<String> DESCRIPTION = new ClassValue<>() {
        @Override protected String computeValue(Class<?> type) {
            computed.incrementAndGet();
            return type.getSimpleName() + " has " + type.getDeclaredFields().length + " fields";
        }
    };

    record Point(int x, int y) {}

    public static void main(String[] args) throws Exception {
        DESCRIPTION.get(Point.class);          // warm up so the count below is deterministic
        DESCRIPTION.get(String.class);
        Thread[] ts = new Thread[4];
        for (int i = 0; i < ts.length; i++) {
            ts[i] = new Thread(() -> {
                for (int j = 0; j < 1000; j++) {
                    DESCRIPTION.get(Point.class);
                    DESCRIPTION.get(String.class);
                }
            });
            ts[i].start();
        }
        for (Thread t : ts) t.join();
        System.out.println(DESCRIPTION.get(Point.class) + "; computed " + computed.get() + " times");
    }
}
```

`ClassValue` is the JVM's purpose-built per-class cache: values are attached to the `Class` object, so they do not keep a class loader alive the way a static `Map<Class<?>, …>` would, which avoids the class-loader leaks common in redeployable applications. `computeValue` may run more than once if two threads race on the first lookup, but only one result is kept. The demo warms both entries up first, so the 4,000 lookups from the threads all hit the cache and the count stays at 2.
:::

:::drill code rating=1200
Show the difference between `Class.forName(name)` and `Class.forName(name, false, loader)`: the first initialises the class, the second only loads it.

```java run=c02-c-forname
}
```

JDBC drivers used to rely on the initialising form: `Class.forName("com.mysql.Driver")` ran the driver's static block, which registered it with `DriverManager`. Since JDBC 4 drivers are discovered through `ServiceLoader` instead.
:::

## Cheat sheet {#ch02-cheatsheet .th}

- Phases: load (bytes → class in metaspace), link (verify, prepare defaults, resolve lazily), initialise (`<clinit>`: static initialisers in source order).
- Initialisation triggers: `new`, static method call, non-constant static field access, `Class.forName(name)`, subclass init, `main` class. Not: `Foo.class`, `new Foo[n]`, compile-time constants.
- Static members initialise the **declaring** class only (`Sub.inheritedStatic` does not run `Sub`'s init).
- `static final` primitives/Strings with constant initialisers are inlined into callers; changing them needs a recompile of the callers.
- Instance order: defaults → `super(…)` → field initialisers/instance blocks in order → constructor body. Overridable calls from constructors see unset fields.
- Loaders: bootstrap (`null`), platform, application; parent delegation; `findClass` for custom sources; class identity = name + defining loader.
- Class init is thread-safe and happens once → holder idiom for lazy singletons.
- Failing `<clinit>` → `ExceptionInInitializerError` once, then `NoClassDefFoundError: Could not initialize class` forever.
- `ClassValue` for per-class caches without leaking loaders.
